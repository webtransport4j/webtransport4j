# WebTransport4J Kubernetes Enterprise Clustering Guide

Deploying WebTransport (HTTP/3 over QUIC/UDP) across a multi-pod Kubernetes cluster requires specialized handling for UDP load balancing, stateless connection resumption, and cluster-wide telemetry aggregation.

## 🔑 Crucial Cluster Requirements & Solutions

### 1. Stateless QUIC Connection Resumption & Migration
* **Challenge**: When a mobile client switches networks (e.g., from Wi-Fi to 5G), the UDP 4-tuple changes. A cloud load balancer may route the next UDP packet to **Pod 2** instead of **Pod 1**.
* **Solution**: WebTransport4J includes [`HmacQuicTokenHandler`](file:///Users/sam/Documents/GitHub/webtransport4j/src/main/java/io/github/webtransport4j/server/HmacQuicTokenHandler.java). All pods in the Deployment mount the shared `CLUSTER_HMAC_KEY` from the Kubernetes Secret. Any pod can cryptographically validate 0-RTT resumption tokens and stateless reset tokens generated by any other pod in the cluster.

### 2. UDP Source IP Preservation (`externalTrafficPolicy: Local`)
* **Challenge**: Standard Kubernetes `ClusterIP` SNATs UDP traffic, replacing the client's real IP with the node IP. This prevents accurate BBR congestion control, IP rate limiting, and connection migration tracking.
* **Solution**: The `Service` specifies `externalTrafficPolicy: Local`. The Cloud Load Balancer routes directly to nodes with active pods without extra NAT hops.

### 3. Cluster-Wide Observability Aggregation
* **Challenge**: When 10 pods run in Kubernetes, each pod tracks its own local sessions and streams.
* **Solution**: Each pod's `WebTransportOtlpMetricsListener` tags metrics with `k8s.pod.name` and streams them to the cluster OpenTelemetry Collector. The collector and Prometheus aggregate:
  - `sum(webtransport_sessions_active)`: Total active sessions across the entire fleet.
  - `sum(rate(webtransport_datagrams_sent_total[1m]))`: Global datagram throughput.
  - `webtransport_quic_rtt_seconds`: P50, P90, and P99 latency percentiles across all nodes.
  - The WebTransport Dashboard displays both cluster totals and per-node breakdowns.

## 🚀 Deployment Instructions

### Step 1: Apply Kubernetes Manifests
```bash
kubectl apply -f k8s/webtransport4j-deployment.yaml
kubectl apply -f k8s/webtransport4j-hpa.yaml
kubectl apply -f k8s/dashboard-deployment.yaml
```

### Step 2: Verify Pods & Services
```bash
kubectl get pods -n webtransport-prod
kubectl get svc -n webtransport-prod
```

### Step 3: Monitor Autoscaling
```bash
kubectl get hpa -n webtransport-prod --watch
```
The HPA will automatically scale pods between 3 and 25 replicas depending on active load and connection concurrency.
